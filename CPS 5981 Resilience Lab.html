Resilience Engineering

20 pointsMemo 7 · 10 pts$0 · localhost only≈ 90 min

Which single failure should this system definitely survive?

You will run a small system that looks redundant, write down what you predict will happen when parts of it fail, push that prediction, then break it on purpose and measure what really happens. The gap between prediction and measurement is your finding.

Ground rules

  • Zero cost. GitHub Codespaces free monthly allowance or Docker on your own machine. No cloud account, no card.
  • Nonproduction only. Everything binds to 127.0.0.1. Juice Shop is deliberately vulnerable.
  • Plan first. Push injection-plan.md before your first fault. The push time is compared with your first stop/pause event.
  • One fault at a time, each with an abort condition and a restore command.
The trapWriting the plan after the injection is faster and produces a tidier document. It also destroys the only finding this unit generates. A plan pushed after the first fault scores 0 of 5.

Measure the steady state

  
Before you break anything, define normal with a number. Run the probe for 30 seconds and look at it.

  
From labs/unit07
./probe.sh 30 > ../../submissions/unit07/results/probe-baseline.csv
column -s, -t ../../submissions/unit07/results/probe-baseline.csv | head -20
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/edge-health

  
Expected: every row is 200, times are well under a second, and served_by alternates between 172.28.7.11 and 172.28.7.12 for the routes that reach a replica. Also open http://127.0.0.1:8080 (in Codespaces, use the Ports tab → port 8080 → Open in Browser) and confirm the shop loads.

  
Read the edge config before you predict. Find these in nginx.conf: which routes go through auth_request, what each timeout is, what proxy_next_upstream retries, and what /edge-health actually checks. Your predictions should cite them.

Task 4 · Reduce the radius, then re-measure

  
Make one degradation decision in edge/nginx.conf and write down why. Options include: decide which routes really need identity and serve public reads without it; shorten the identity timeout so a hung provider fails fast; add a health endpoint that tells the truth. Then reload the edge and repeat the worse of E2 or E3 as E2b.

  
After editing edge/nginx.conf
R=../../submissions/unit07/results
docker compose exec edge nginx -t && docker compose exec edge nginx -s reload
git diff edge/nginx.conf > $R/task4.diff
./probe.sh 150 > $R/probe-E2b.csv &
sleep 30; docker compose stop idp      # or: docker compose pause idp
sleep 60; docker compose start idp     # or: docker compose unpause idp
wait

Analysis Memo 7 · 10 points · two pages maximum

  
Chapter 7 discusses system-of-systems assurance. Describe one failure in a system the lab target depends on but does not control, and say what evidence you would need to know it had occurred.

  

    
Strong memos
    
      
  • Name a concrete external dependency: the container image registry, DNS, the Codespaces control plane, the upstream Juice Shop project, the certificate authority.
    • 
      
  • Describe the failure and its route into the lab target.
    • 
      
  • Specify observable evidence: a log line, an event, a status signal, a digest mismatch. "We would notice" is not evidence.
    • 
      
  • Connect to Mead & Woody Ch. 7: why no single owner sees this failure.
    •
